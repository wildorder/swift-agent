# Contributing to Swift Agent

Thanks for contributing! Swift Agent is licensed under the
[Apache License 2.0](./LICENSE). This document covers the contribution terms
and the day-to-day development workflow.

## Contribution terms

### Developer Certificate of Origin (DCO)

This project uses the **Developer Certificate of Origin 1.1** — see the
[`DCO`](./DCO) file for the full text. By signing off a commit you certify the
statements in that file: that you have the right to submit the contribution
under the project's open-source license.

**Every commit must carry a `Signed-off-by` trailer.** Add it with:

```sh
git commit -s
```

which appends a line like:

```
Signed-off-by: Your Name <your.email@example.com>
```

CI **enforces** this on every pull request
([`.github/workflows/dco.yml`](./.github/workflows/dco.yml) runs
[`scripts/check-dco.mjs`](./scripts/check-dco.mjs)): a PR containing any commit
without the trailer fails the check. Two exemptions: merge commits (any
commit with more than one parent — GitHub's merge button, merge queue, and
test-merge commits are generated by the platform, not authored by a
contributor), and history predating the DCO's adoption, which is not
retroactively rejected.

If you forgot to sign off, amend or rebase:

```sh
git commit --amend -s --no-edit          # last commit
git rebase --signoff origin/main         # every commit on the branch
```

### You retain your copyright

**Contributors retain the copyright in their contributions.** There is no
copyright assignment. A knowingly accepted consequence: the project cannot be
relicensed later without the permission of every copyright holder.

### No CLA

There is **no Contributor License Agreement** and none is needed: Apache-2.0
§5 already licenses every intentionally submitted contribution under the same
terms as the project ("inbound = outbound"). The DCO sign-off is the only
formality.

## Development workflow

This is a pnpm + Turborepo monorepo (Node 22 LTS, TypeScript strict, ESM).

```sh
pnpm install       # install workspace dependencies
pnpm build         # build every package
pnpm typecheck     # type-check every package
pnpm lint          # lint every package
pnpm test          # run unit tests
```

All four gate commands (`build`, `typecheck`, `lint`, `test`) must be green
before a PR can merge. Integration and acceptance suites
(`pnpm test:integration`, `pnpm test:acceptance`) need Docker; note the root
`test/` tree is excluded from `pnpm typecheck`/`pnpm lint` and is validated by
running those suites.

Every user-facing change to a publishable package ships with a changeset:

```sh
pnpm changeset
```

See [`docs/policies/versioning.md`](./docs/policies/versioning.md) for how
bumps are classified, and [`RELEASING.md`](./RELEASING.md) for how releases are
cut (a manual, owner-triggered workflow — contributors never publish).
